# Colony Zero

**四名先驱，三十周时间，一个可以称为家的地方。**

Colony Zero 是一款使用 Python 和 Tkinter 制作的回合制科幻殖民地经营游戏。你将从一座小小的着陆基地出发，建设设施、分配补给、接纳居民，并决定如何应对突发事件。在补给船经过之前，殖民地需要修好接应信标，也需要有人坚持到那一天。

**当前版本：V3.3「给家园更多空间」**  
[English README](README.md)

## 游戏特色

- 5×5 地图、四种建筑，每种设施可升级一次。
- 管理食物、能源、材料和人口，同时关注住房与幸福度。
- 十二类双选项事件，从太阳风暴到殖民地聚餐。
- 主动暂停或恢复生产，在粮食储备与能源需求之间安排取舍。
- 下周预测、殖民地纪事，以及反映经营成果的结局评级。
- JSON 存取档、即时中英文切换和可选短音效。

## 开始游戏

需要 **Python 3.10 或以上版本、Tkinter 和桌面图形环境**。窗口可调整大小，最小内容区为 **980×680**。项目仅使用 Python 标准库，无需通过 `pip` 安装额外包。

在包含 `main.py` 的文件夹中打开终端，运行：

```bash
python main.py
```

Windows 也可以运行 `py main.py`；macOS 或 Linux 可按本机设置使用 `python3 main.py`。使用 IDLE 时，打开 `main.py` 并按 **F5**。

可以用下面的命令检查 Tkinter：

```bash
python -m tkinter
```

游戏会打开独立的桌面窗口。使用没有图形显示的网页终端时，需要把项目下载到本地桌面 Python 环境运行。

## 你的第一座殖民地

开局拥有四名先驱、中央总部，以及 20 食物、12 能源和 42 材料。目标是：**存活三十周，并在推进到第30周之前完成全部三阶段信标。**

1. 点击空地，选择建筑，再点击建造。
2. 查看资源卡片下方的小数字，了解下一次结算的预计净变化。
3. 点击「推进一周」，结算生产、居民消耗和时间。
4. 议会事件出现后，先选择应对方案，再继续经营。
5. 随着信标阶段解锁，提前准备施工机会与所需补给。

**每周只有一次施工机会**：新建、升级或总部工作三选一。先建立食物和能源供应，再发展材料生产，逐步扩大殖民地。「周报」提供完整计算，「帮助」可随时查看规则。

## 建筑与补给

下表费用均以材料支付；生产和耗电按设施运行且获得供电时的每周数值计算。

| 建筑 | 建造费用 | 一级效果 | 升级费用 | 二级效果 |
|---|---:|---|---:|---|
| 太阳能发电站 | 10 | 生产7能源 | 8 | 生产12能源 |
| 水培农场 | 12 | 消耗3能源，生产6食物 | 10 | 消耗4能源，生产9食物 |
| 采矿设施 | 14 | 消耗3能源，生产6材料 | 10 | 消耗4能源，生产9材料 |
| 住宅模块 | 12 | 增加4住房，消耗1能源 | 8 | 增加6住房，消耗1能源 |

每名居民每周需要 **1 食物**。每四周检查一次新增居民；住房、食物、电力和幸福度满足条件时，殖民地会迎来新成员。人口增长至少需要 **40 幸福度**。

布局也会影响经营：有电的农场与住宅相邻，每周额外生产 **2 食物**；住宅邻接未主动停用的矿场，每周损失 **2 幸福度**，全殖民地噪声损失最多为4。相邻关系只计算上下左右。

电力优先供应住宅，其次是农场，最后是矿场。地图会标记下一次结算预计缺电的设施。食物储备充裕时，可以选中农场或矿场，点击「暂停生产」，停止其产出和耗电，不占施工机会。停用矿场也会停止贡献邻接噪声。需要时点击「恢复生产」；停用期间，临时效果仍正常倒计时。

### 应急配给

每局可使用两次，使下一次结算的口粮需求减半，向上取整。每次立即消耗 **8 幸福度**，并暂停该次人口增长。悬停按钮可查看说明；首次启用会先显示效果预览，确认后生效。

### 接应信标

| 阶段 | 完成以下周数后解锁 | 材料 | 能源 |
|---|---:|---:|---:|
| 第一阶段 | 6 | 18 | 8 |
| 第二阶段 | 14 | 28 | 18 |
| 第三阶段 | 22 | 36 | 32 |

每阶段占用一次施工机会，并增加3幸福度。请在 **第29周及之前** 完成；目标栏会显示当前进度、下一阶段费用和资源缺口。

## 事件、纪事与结局

三十周内会遇到十二次议会事件。不同方案可能消耗补给、改变居民状态，或让生产受到几周影响。选项卡会显示代价、后果，以及可选方案的下一次结算预览。中后期费用随人口和远征阶段增长。

主界面的「殖民地纪事」展示居民反应与重要时刻。「阅读历史」可查看保留的故事和操作记录，周报也会回顾已记录的殖民地经历。

人口归零时，远征结束。居民存活却没有完成信标，会得到「失联殖民地」结局。成功获救后，殖民地会获得经营评级：

- **新伊甸（New Eden）**：人口至少13、幸福度至少80、分数至少390。
- **繁荣殖民地（Prosperous Colony）**：人口至少11、幸福度至少65、分数至少300。
- **艰难前哨（Struggling Outpost）**：成功生存并获救，家园仍有继续成长的空间。

## 操作与设置

| 控件 | 功能 |
|---|---|
| 地图点击／方向键 | 选择地块；使用方向键前先点击地图 |
| 新游戏／演示（种子7） | 开始随机远征／可重复体验的远征 |
| 保存／读取 | 保存或恢复 JSON 存档 |
| 周报／帮助 | 查看生产详情／游戏规则 |
| 阅读历史 | 查看保留的殖民地叙事与操作历史 |
| 语言 | 即时切换英文与简体中文 |
| 音效／动态 | 开关短音效／减少视觉效果 |

游戏默认英文，音效默认关闭。音效使用 Windows 标准库 `winsound`，其他平台以静音方式游玩。建筑图形由 Tkinter Canvas 绘制，随附 WAV 音效由音调合成。

存档包含地图、资源、生产开关、事件顺序和进度。旧存档保留原来的远征规则；选择「新游戏」可开始包含生产控制的当前三十周版本。

## 体验一个存档场景

点击「读取」，选择 `examples/` 内的文件。

| 文件 | 可以体验什么 |
|---|---|
| `power_management_before.json` | 选中A1，对比暂停前、暂停后与恢复后的生产预测 |
| `week05_ration_preview.json` | 了解应急配给如何影响粮食危机 |
| `week14_arrival_choice.json` | 决定是否接纳两名勘探员 |
| `week23_beacon_ready.json` | 完成最后一阶段信标 |
| `week29_before_arrival.json` | 推进到最后一周，查看建设完成的殖民地 |

15个当前版本场景直接放在 `examples/` 中。早期存档按游戏版本分组，用于兼容性测试：

```text
examples/
├── *.json          # 15个当前V3.3场景
└── legacy/
    ├── V2.x/       # V2.0与V2.1共用的8个存档
    ├── V3.0/       # 10个存档
    └── V3.1/       # 12个存档
```

## 项目结构与测试

| 文件 | 职责 |
|---|---|
| `main.py` | 程序入口 |
| `engine.py`、`events.py` | 游戏规则、生产、预测与事件 |
| `gui.py`、`dialogs.py`、`localized_widgets.py` | 界面、阅读窗口与交互控件 |
| `visuals.py`、`soundfx.py` | 矢量图形与可选音效 |
| `i18n.py` | 界面翻译 |
| `narrative.py`、`polish.py`、`chronicle.py` | 故事、居民反应与纪事呈现 |
| `persistence.py` | JSON 存取、验证与版本迁移 |
| `assets/`、`examples/`、`tests/` | 音效、场景存档与自动化测试 |

引擎使用独立二维列表存储地块、等级和生产开关；文件I/O使用 JSON 保存远征；异常处理负责报告非法操作或文件问题，并保留当前殖民地。

在项目目录运行测试：

```bash
python -m unittest discover -s tests -v
```

测试套件包含 **202项测试**，覆盖规则、预测、存取档、兼容性和界面行为。图形界面测试需要桌面显示环境。V3.3 已在 Windows、Python 3.12.14、Tk 8.6.12 环境验证。
